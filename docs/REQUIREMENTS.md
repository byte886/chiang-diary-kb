# 需求说明（REQUIREMENTS）

> 来源：`docs/采集方案_v2.md`（v2.0，2026-09-29）。本文是可执行需求口径。

## 1. 项目目标

尽可能完整获取《蒋中正日记》官方原始数字影像，为每个档案件建立对应 PDF 与转稿文本。
最终是一个结构清晰、可由文件系统直接管理的本地资料库。

明确不做：数据库、本地全文检索、RAG、向量数据库、复杂 Web UI。

## 2. 数据来源与身份

- 第一优先级：国史馆 <https://ahonline.drnh.gov.tw/> 的官方数字影像
- 匿名访客、无账户；强制登录/验证码/明确禁止自动化即暂停商量，不绕过
- 转稿优先级：官方转稿 → 正式出版物 → 可靠公开转稿 → GitHub
  （mahavivo/Chiang-Kai-shek）→ 自 OCR
- 无论转稿来自何处，原始图像 PDF 尽量来自官方档案

## 3. 每件交付物

```text
YYYY/<典藏号>/
├── original/             官方原始图片（001.jpg、002.jpg …）
├── <典藏号>.pdf          全部原始影像按官方顺序封装
├── <典藏号>.md           转稿，逐页对应（## Page N）
└── metadata.json         见下
```

metadata.json 至少包含：典藏号、年份、日期、标题、来源、archive_url、
image_page_url、download_url、PDF 文件名与 SHA-256、转稿文件名/来源/类型。

## 4. 质量原则

- 原图不修改、不额外加水印、不降分辨率；PDF 不过度压缩、不 OCR 覆盖原图
- 官方直接提供 PDF 时原样保存、不重新转换
- PDF 与原图均计算 SHA-256
- OCR 输出保留页码、逐页对应；不自动润色、不擅转繁简、不改写日期/人名/地名；
  不确定处用 `[OCR不确定]`、`[疑似：XXX]` 标注且不删除原始 OCR

## 5. 下载器要求

- 支持：断点续传、自动重试、超时、HTTP 429 / 5xx、SHA-256、下载日志
- 初始并发 2、请求间隔 1–3 秒；确认稳定后再调整
- 状态文件：`download_status.jsonl`（每件状态）、`progress.json`（总体进度）
- 错误页检测：HTTP 200 仍须校验 Content-Type、文件大小、Magic Bytes、可解码

## 6. 年份策略

- 1924：据载日记已遗失，目录保留 `1924/README.md` 说明，不视为下载失败
- 1955–1972：未确认全部开放在线原始影像前，标 `NOT_YET_CONFIRMED_ONLINE`；
  不伪造数据、不盲目重试、不用不明来源充当官方原图；官方开放后增量接入即可

## 7. 验收标准

1. 尽可能多的档案件拥有与典藏号对应的、忠实于官方影像的 PDF
2. 每件尽可能有与原始图像逐页对应的转稿
3. 任意 PDF 可追溯年份、日期、典藏号与国史馆原始页面
4. 用户可直接打开 PDF 看手稿、打开 MD 读转稿，且 Page N 一一对应
