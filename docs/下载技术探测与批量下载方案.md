# 《蒋中正日记》下载技术探测与批量下载方案

> 本章节是整个项目最关键的技术实施部分。
>
> **严禁在没有实际测试之前假定国史馆影像可以直接用 cURL 下载，也严禁假定必须使用 Chrome。**
>
> 第一阶段的目标不是立即批量下载，而是确定：
>
> **“国史馆的‘下载影像’究竟是一个可以复现的 HTTP 请求，还是必须依赖浏览器运行环境。”**

---

# 1. 总体技术路线

采用：

```text
Chrome / Chromium + Playwright
            ↓
      观察真实行为
            ↓
     捕获 Network 请求
            ↓
    分析实际下载协议
            ↓
 ┌──────────┴──────────┐
 ↓                     ↓
可以复现 HTTP          无法独立复现
 ↓                     ↓
curl/httpx             Playwright
requests               / Chromium
 ↓                     ↓
批量下载               批量下载
```

因此：

> **Chrome/Chromium 是第一阶段的“协议侦察工具”，不是默认的最终下载工具。**

---

# 2. 为什么不能一开始直接 cURL

不能直接假定：

```bash
curl "https://ahonline.drnh.gov.tw/..."
```

就可以获得图片。

因为“下载影像”可能存在以下情况：

```text
A. 普通 GET
B. 带 Cookie 的 GET
C. 带 Referer 的 GET
D. 带 Session 的 GET
E. 带 CSRF Token 的 GET/POST
F. JavaScript 动态生成下载 URL
G. AJAX 获取 token 后再下载
H. POST 提交参数
I. 临时签名 URL
J. 多步请求后产生下载
K. 浏览器端 JS 拼接真实 URL
L. 下载接口本身返回 ZIP/PDF
M. 浏览器收到图片后再处理
```

因此必须先观察真实网络行为。

# 5. 不要只监听一个 request

点击下载后可能发生：

```text
Request 1
页面请求 token

Request 2
API 请求影像信息

Request 3
生成下载地址

Request 4
真正下载文件
```

所以不能简单：

```text
“找到一个 JPG 请求”
```

就认为已经找到完整协议。

必须分析：

```text
点击前
    ↓
点击
    ↓
点击后
```

完整请求链。

# 6. Playwright 第一版监听代码逻辑

AI IDE 应实现类似：

```python
page.on("request", capture_request)
page.on("response", capture_response)
page.on("requestfailed", capture_failed_request)
```

然后：

```python
await page.goto(archive_page)

# 等待页面稳定

# 定位“下载影像”

# 点击

# 等待所有相关网络请求结束
```

所有请求保存到：

```text
logs/
└── 002-150101-00037-141-network.jsonl
```

# 8. 第一项判断：真正的文件是什么

点击“下载影像”后，首先判断最终返回的内容。

可能是：

```text
image/jpeg
image/png
image/tiff
application/pdf
application/zip
application/octet-stream
text/html
```

必须实际验证。

不能看到：

```text
HTTP 200
```

就认为是成功。

---

# 9. 判断是不是直接文件下载

如果发现：

```text
GET https://.../xxx
```

并且：

```text
Content-Type: image/jpeg
```

或者：

```text
Content-Disposition: attachment
```

那么很可能可以直接使用：

```bash
curl
```

或者：

```python
httpx
```

复现。

---

# 10. 第一种情况：完全公开的 GET

如果发现：

```text
GET /download/xxxxx
```

不需要：

```text
Cookie
Token
Referer
Session
```

那么最终 downloader 可以直接：

```bash
curl -L -o output.jpg "DOWNLOAD_URL"
```

这是最简单的情况。

批量下载优先使用：

```text
curl
```

或者：

```text
httpx
```

---

# 11. 第二种情况：需要 Cookie

例如浏览器请求：

```text
Cookie:
PHPSESSID=...
```

而不带 Cookie：

```text
HTTP 403
```

那么需要：

```text
Playwright
    ↓
建立正常 session
    ↓
获取 Cookie
    ↓
交给 httpx/curl
    ↓
批量下载
```

不要因此马上决定：

> “必须 Chrome 下载。”

因为 Cookie 可以被 HTTP client 使用。

---

# 12. 第三种情况：需要 Referer

如果服务器要求：

```text
Referer:
https://ahonline.drnh.gov.tw/...
```

那么 httpx 仍然可以模拟：

```python
headers = {
    "Referer": "...",
    "User-Agent": "..."
}
```

因此：

```text
需要 Referer
≠
必须 Chrome
```

---

# 13. 第四种情况：需要 Session

如果下载 URL 只能在正常浏览档案页面后工作：

```text
打开档案页面
        ↓
建立 Session
        ↓
下载
```

测试：

```text
新 HTTP session
        ↓
直接请求下载 URL
```

如果失败：

```text
Playwright 建立 session
        ↓
提取 Cookie
        ↓
httpx 使用同一个 session
```

---

# 14. 第五种情况：需要 Token

例如：

```text
页面
 ↓
API
 ↓
取得 token
 ↓
下载
```

则首先确认 token 是：

```text
静态 token
```

还是：

```text
每次动态 token
```

如果 HTTP client 可以完成：

```text
GET page
 ↓
parse token
 ↓
GET API
 ↓
download
```

那么仍然不需要 Chrome。

---

# 15. 第六种情况：JavaScript 动态生成 URL

例如页面源码没有：

```text
download_url
```

但是 JS 执行后出现：

```text
https://.../temporary/xxxxx
```

此时需要进一步分析：

```text
JS source
Network
XHR/fetch
```

确认 URL 如何生成。

如果能够还原：

```text
JavaScript algorithm
```

或者直接找到：

```text
API endpoint
```

则仍然可以考虑独立 HTTP 下载。

---

# 16. 第七种情况：Blob 下载

如果 Chrome 中出现：

```text
blob:https://...
```

不能直接把：

```text
blob:
```

当作服务器下载地址。

必须继续向前追踪：

```text
Blob
 ↑
fetch/XHR
 ↑
真正 HTTP 请求
```

真正需要下载的是：

```text
fetch/XHR
```

返回的数据。

---

# 17. 第八种情况：浏览器端拼接 PDF

如果点击“下载影像”后：

```text
服务器返回多张图片
        ↓
JavaScript
        ↓
浏览器生成 PDF
```

那么需要判断：

```text
服务器是否本来就提供原始图片
```

如果提供：

```text
直接保存原始图片
        ↓
本地生成 PDF
```

优于：

```text
Chrome 下载浏览器生成 PDF
```

因为本地 PDF 可以确保：

```text
图片顺序
原始分辨率
页面对应关系
```

---

# 18. 第九种情况：服务器返回 ZIP

如果：

```text
Content-Type:
application/zip
```

则：

```text
下载 ZIP
 ↓
验证 ZIP
 ↓
解压
 ↓
取得原始图片
 ↓
生成 PDF
```

不要把 ZIP 本身作为最终档案 PDF。

---

# 19. 第十种情况：服务器直接提供 PDF

如果最终响应：

```text
Content-Type:
application/pdf
```

那么：

> **优先保存官方 PDF，不要重新生成。**

流程：

```text
官方 PDF
 ↓
原样保存
 ↓
SHA256
 ↓
metadata
```

---

# 20. 判断“能否脱离 Chrome”的标准

必须实际做一次实验。

得到：

```text
browser_download
```

之后：

```text
独立 HTTP client
```

重新下载同一个文件。

比较：

```text
HTTP status
Content-Type
Content-Length
文件格式
文件大小
SHA-256
```

如果一致：

```text
独立 HTTP 下载 = 成功
```

---

# 21. SHA-256 比较

例如浏览器获得：

```text
browser_file.sha256
```

HTTP client 获得：

```text
http_file.sha256
```

如果：

```text
browser_sha256 == http_sha256
```

则说明：

> HTTP client 已经成功复现浏览器下载。

这是非常重要的验收条件。

---

# 22. 如果 cURL 成功

如果发现：

```bash
curl -L ...
```

可以完整下载：

```text
浏览器文件
=
cURL 文件
```

则最终方案：

```text
Playwright
    ↓
只用于发现协议
```

正式批量：

```text
cURL / httpx
    ↓
批量下载
```

推荐优先：

```text
httpx
```

因为 Python 程序更容易实现：

* 重试
* 并发
* 日志
* SHA256
* 状态
* 断点

---

# 23. 如果 cURL 不成功，但 Playwright 可以

不要强行逆向。

直接采用：

```text
Playwright Downloader
```

结构：

```text
Chromium
 ↓
打开档案
 ↓
下载影像
 ↓
保存文件
```

但是仍然需要：

```text
低并发
限速
失败重试
断点
日志
```

---

# 24. 最终下载器不是预先决定的

必须由测试结果决定：

```text
CASE A
直接 HTTP
→ curl/httpx

CASE B
HTTP + Cookie
→ Playwright 建 session + httpx

CASE C
HTTP + Token
→ 自动获取 token + httpx

CASE D
复杂 JS
→ Playwright

CASE E
Blob
→ 追踪 fetch/XHR

CASE F
浏览器生成 PDF
→ 下载原图 + 本地生成 PDF
```

# 30. 最重要的验收标准

不能仅仅说：

> “curl 可以访问。”

必须证明：

```text
Chrome 下载的文件
        =
HTTP client 下载的文件
```

最可靠的判断：

```text
SHA-256 相同
```

# 31. 批量下载前必须完成的事情

只有以下全部完成后，才允许批量下载：

```text

[ ] 确认 Content-Type

[ ] 确认 Cookie/Session/Token 要求

[ ] 完成一次独立 HTTP 测试

[ ] 对比浏览器和 HTTP 文件 SHA256

[ ] 确定最终 downloader

[ ] 完成一个 item

[ ] 完成 10 个 item

```

# 33. AI IDE 必须遵守的第一条规则

**不要先写批量 Downloader。**

第一件事：

> **把 `002-150101-00037-141` 的“下载影像”完整跑通。**

第二件事：

> **尝试用 cURL/httpx 完全复现。**

第三件事：

> **比较两个文件 SHA-256。**

第四件事：

> **根据测试结果选择 HTTP Downloader 或 Playwright Downloader。**

第五件事：

> **才开始批量下载。**

# 34. 最终目标

最终每一个成功获取的档案件都应该形成：

```text
002-150101-00037-141/
│
├── original/
│   ├── 001.jpg
│   ├── 002.jpg
│   └── ...
│
├── 002-150101-00037-141.pdf
│
├── 002-150101-00037-141.md
│
└── metadata.json
```

其中：

```text
original/
    ↓
官方数字影像

PDF
    ↓
原始图像的可阅读封装

MD
    ↓
对应转稿

metadata.json
    ↓
记录来源、典藏号、日期、下载方式、SHA256
```

最终原则：

> **先逆向观察正常下载行为，再决定用 cURL/httpx 还是 Chrome/Playwright。不要预设技术路线。**
